**Auth flow:** `/auth/login` → `supabase.auth.signInWithOtp({email, options:{emailRedirectTo: origin/auth/callback}})` → email link → `/auth/callback?code=...` → `exchangeCodeForSession` → redirect `/` (or `next` param).

**Trigger SQL sketch (in migration):**
```sql
create or replace function public.handle_new_user() returns trigger as $$
begin
  insert into public.profiles (id, role, display_name)
  values (new.id, 'employer', coalesce(new.raw_user_meta_data->>'display_name', split_part(new.email,'@',1)))
  on conflict (id) do nothing;
  return new;
end; $$ language plpgsql security definer;
drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created after insert on auth.users for each row execute function public.handle_new_user();
```

**Policies to activate (in migration, replace commented examples):**
- `jobs`: `FOR SELECT TO anon, authenticated USING (true)` (public read).
- `email_subscriptions`: `FOR INSERT TO anon WITH CHECK (true)`, `FOR ALL TO service_role USING (true)`.
- `employer_postings`: `FOR SELECT/INSERT TO authenticated USING (auth.uid()=user_id)`, `FOR ALL TO service_role`.
- `profiles`: `FOR SELECT TO authenticated USING (auth.uid()=id)`, `FOR UPDATE TO authenticated USING (auth.uid()=id)`, `FOR ALL TO service_role`.

**Verify:**
- `npm run typecheck` 0; `npm run lint` 0; `npm run build` succeeds.
- `supabase/auth` pages render; `grep -r "server-only" src/lib/supabase` — server helpers import `server-only` where secret is used.
- Manual: `POST /auth/login` with real email sends magic link (check Supabase Auth logs).

**Commit:** `feat(auth): supabase magic-link + profiles trigger + session middleware`
